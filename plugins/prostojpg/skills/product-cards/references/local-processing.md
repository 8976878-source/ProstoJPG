# Локальная подготовка и сборка

Нужен Python 3.10+ и Pillow. Используй абсолютный путь к `scripts/cards.py` внутри установленного скилла. Локальный desktop Codex может предоставить встроенный Python и Pillow через инструмент загрузки зависимостей рабочего окружения. В других окружениях используй доступный Python. Минимальная установка: `python -m pip install -r requirements.txt` из каталога scripts с применимыми разрешениями пользователя.

## Команды

Сначала скачай исходный ZIP из Codex по [сценарию прямой загрузки](direct-download.md). Подставь действительные абсолютные пути и полученный от пользователя артикул. Пример для режима 2:

```text
python cards.py prepare --source WB_292230616.zip --job-dir job-292230616 --mode 2 --marketplace WB --article 292230616
python cards.py build --job-dir job-292230616 --output WB_292230616_similar.zip
```

Режим 1: `--mode 1`. Режим 3: `--mode 3 --subject product.png`. `prepare` не перезаписывает существующую папку. `build` не перезаписывает существующий ZIP. При повторной обработке используй существующее задание и новое имя результата, если входы не изменились.

Обе команды возвращают JSON в UTF-8 и код 0 при успехе; код 1 и сообщение в stderr при ошибке.

## Файлы задания

- `originals/`: копии исходных фото и видео, порядок галереи сохранён.
- `reference/`: фото своего товара в режиме 3.
- `generated/`: сюда копируются действительные результаты генератора; один файл на фото.
- `job.json`: режим, маркетплейс, артикул, исходные размеры, путь `source`, ожидаемый путь `generated` и имя `output` для каждого фото.

Пример записи фото:

```json
{
  "source": "originals/photo-0001.jpg",
  "original_name": "WB_292230616_01-photo.jpg",
  "width": 900,
  "height": 1200,
  "generated": "generated/0001.png",
  "output": "photos/WB_292230616_01-photo.jpg"
}
```

В режимах 2 и 3 `build` использует только `generated`, а отсутствие хотя бы одного результата блокирует сборку. В режиме 1 использует `source`. Нельзя копировать исходник в generated для имитации успешной генерации.

В готовом ZIP находятся `photos/`, `videos/` при их наличии и `manifest.json`. Манифест содержит фактические размеры фото, исходные размеры, признак полей (`padded`), увеличения (`upscaled`) и счётчики. Пользовательский `job.json` и фото товара в итоговый ZIP не добавляются.

Нормализация: сохраняется точное исходное соотношение сторон, короткая сторона минимум 1200. Кадр вписывается полностью, с белыми полями при необходимости. Обработчик проверяет целостность ZIP и размеры экспортированных файлов.

Файлы очень вытянутых пропорций или более 40 мегапикселей требуют отдельного решения; скрипт явно отклоняет их. Поддержка AVIF зависит от установленной сборки Pillow. Прямой загрузчик сохраняет исходные форматы фото и доступное видео; итоговый обработчик экспортирует фото в JPG.
