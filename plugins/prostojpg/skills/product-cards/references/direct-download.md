# Прямая загрузка исходников из Codex

Нужны управление **внешним Chrome или Яндекс Браузером**, локальный Python 3.10+ с Pillow и сетевой доступ к CDN маркетплейса. Встроенный браузер Codex/IAB запрещён для WB/Ozon в этом сценарии: VPN в нём может блокировать сайты. Архив собирает `scripts/download.py`; кнопка скачивания ZIP расширения не используется.

Сначала прочитай документацию инструментов и список подключённых браузеров. Выбери внешнюю поверхность Chrome/Яндекс (`extension`/`cdp`, не `iab` и не `mcpapps`). При нескольких доступных выбери Chrome, если пользователь не указал другой. Для `cua` при наличии Chrome открывай URL через `cua.createBrowserTab("chrome", url, {sessionName:"📦 ПростоJPG"})` либо привяжи наблюдённую вкладку через фактический внешний browser ID. Для Яндекса используй его обнаруженный ID; не выдумывай название провайдера. Не открывай маркетплейс через default browser, если это ведёт в IAB. При отсутствии управления помоги подключить внешний браузер; не переходи во встроенный. Не отключай и не меняй VPN пользователя.

## Открыть нужную карточку

- WB: `https://www.wildberries.ru/catalog/<артикул>/detail.aspx`.
- Ozon: `https://www.ozon.ru/search/?text=<артикул>`. Из фактических результатов открой ссылку `/product/...-<артикул>/` с точным совпадением числового ID. Можно сразу открыть такую ссылку, уже данную пользователем. Не выбирай первый результат без проверки ID.

Проверь URL открытой карточки, товар и артикул. При CAPTCHA или входе потребуется действие пользователя. Не заменяй публичную карточку API кабинета продавца, не спрашивай API-ключ для скачивания чужой публичной карточки.

## Собрать всю галерею

1. Прочитай документацию доступного браузерного инструмента. Из его DOM/снимка выбери основную галерею карточки и её наблюдаемый селектор. Открой увеличенную галерею штатным кликом, если это даёт доступ ко всем фото. Выбранный корень должен исключать рекомендации и отзывы и соответствовать одному элементу.
2. Прочитай `scripts/gallery.js`. Если инструмент поддерживает чтение DOM через evaluation, передай **только выражение функции `collectProductGallery`**, с параметрами `marketplace`, `article`, `selector`. Функция читает URL изображений, srcset, видео, inline-данные и фоновые изображения внутри выбранной галереи. Не исполняй блок CommonJS `module.exports`; не инжектируй код расширения. При отсутствии evaluation извлеки эти URL из доступного DOM-снимка/атрибутов инструментами браузера.
3. Посети каждую миниатюру/страницу галереи, включая видео, кликами/клавишами инструмента браузера. После загрузки очередного слайда повтори чтение. Объедини наблюдённые `media` в порядке галереи; не ограничивайся первыми 18 слайдами. Миниатюры и большие версии одной фотографии дедуплицируются загрузчиком после нормализации `/big/` для WB и `/wc1200/` для Ozon. Если одновременно присутствуют разные форматы одного изображения, выбери одну наблюдённую лучшую версию на позицию галереи.
4. Сверь уникальные позиции с фактическими миниатюрами/счётчиком галереи. Сами результаты чтения имеют `complete: false`, поскольку один DOM-снимок не доказывает полноту. Только после проверки всех позиций запиши `complete: true` и `expected_count` — общее количество уникальных фото **и видео**. Не объявляй полноту по одному исчезнувшему или повторившемуся слайду.
5. Сохрани `gallery.json` файловым инструментом в новой папке задания. Минимальная форма ниже; URL в примере обозначает формат и должен быть заменён действительным наблюдённым URL.

```json
{
  "marketplace": "WB",
  "article": "123",
  "page_url": "https://www.wildberries.ru/catalog/123/detail.aspx",
  "complete": true,
  "expected_count": 1,
  "media": [
    {"type": "image", "url": "https://basket-01.wbbasket.ru/vol0/part0/123/images/big/1.webp"}
  ]
}
```

## Скачать, затем обработать

Используй действительные абсолютные пути и новое имя ZIP:

```text
python download.py --manifest gallery.json --output WB_123_originals.zip
python cards.py prepare --source WB_123_originals.zip --job-dir job-123 --mode 1 --marketplace WB --article 123
python cards.py build --job-dir job-123 --output WB_123_ready.zip
```

В режимах 2/3 замени `--mode`, приложи `--subject` для режима 3 и выполни генерацию **всех** фото до `build`. Финальные пропорции и минимум 1200 по короткой стороне обеспечиваются `build`, исходный ZIP содержит неизменённые скачанные файлы.

Загрузчик проверяет домены CDN, HTTPS, соответствие карточки артикулу, полноту списка, формат файлов, размеры и целостность ZIP. Изображения на WB должны иметь артикул в пути. Отзывы и интерфейс исключаются. При отсутствии улучшенной версии (HTTP 404) он использует наблюдённый исходный URL. Временные ошибки повторяет до трёх попыток; HTTP 403, CAPTCHA, неизвестный CDN и потоки M3U8/MPD требуют решения, а не ложного успеха. Cookies и токены браузера не читаются.

## Если VPN мешает HTTP-загрузчику

Если карточка и медиа доступны во внешнем браузере, но локальный HTTP-процесс не может скачать файлы, используй документированное скачивание **отдельных медиа** этого внешнего браузера. Например, доступный `locator.downloadMedia()` скачивает наблюдённый `img`/`video`/ссылку и возвращает реальный локальный путь. Читай документацию именно подключённого инструмента; используй наблюдённый однозначный локатор, посещай каждый слайд и сохраняй оригинальный порядок. Не создавай скрытые ссылки, не инжектируй клики/fetch и не пытайся запустить API расширения.

Для каждой записи `media` добавь `local_path` — действительный абсолютный путь возвращённого файла. Оставь проверенные `type`, `url`, `page_url`, `expected_count`, `complete`. Не придумывай путь сохранения. Затем выполни:

```text
python download.py --manifest gallery-with-files.json --output WB_123_originals.zip --from-local
```

В этом режиме загрузчик не делает сетевых запросов: проверяет каждый файл и сам создаёт ZIP. Если инструмент не умеет сохранять отдельные медиа или файлы недоступны локальному процессу, сообщи об этом. Сохраняются те же проверки полноты, форматов и запрет перезаписи. Так архив всё равно собирается Codex независимо от браузерной ZIP-загрузки расширения.

Успех: код 0 и JSON `archive`, `image_count`, `video_count`, `complete: true`. При любой ошибке итоговый ZIP не создаётся, существующие файлы сохраняются. Манифест остаётся для повторной попытки. Не удаляй проблемные элементы списка ради `complete: true`. Если пользователь отдельно выбрал только фото, создай отдельный проверенный манифест фото и явно укажи, что видео в этом архиве отсутствует.
