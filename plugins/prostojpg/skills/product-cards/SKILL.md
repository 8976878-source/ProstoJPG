# ПростоJPG от ПростоСеллер

Создай полный набор фото и новый ZIP на компьютере пользователя. Используй скачанные фото как исходники, доступный генератор изображений для творческих изменений и локальный скрипт только для подготовки, нормализации размеров и упаковки. Плагин не предоставляет свою модель или доступ к генерации сверх возможностей окружения.

## Диалог при вызове

Если сообщение начинается с `/ProstoJpg-1`, `/ProstoJpg-2` или `/ProstoJpg-3`, режим уже выбран: соответственно 1, 2 или 3. При прямом вызове `$prostojpg-1`, `$prostojpg-2`, `$prostojpg-3` действует тот же выбор. Регистр команды не важен. Прочитай только выбранный режим и общие шаги; не показывай меню повторно. Сохрани артикул, маркетплейс и вложение из сообщения. При наличии Python проверяй сообщение через `scripts/select_mode.py`, передавая его одним безопасно экранированным аргументом; JSON содержит `mode`, `arguments`, `requires_subject`. Этот скрипт выбирает режим, но не запускается автоматически клиентом Codex и не регистрирует системную slash-команду. При неизвестном номере или нескольких командах в одном сообщении уточни один режим, не начинай скачивание и генерацию.

Эти slash-команды — текстовые обращения к плагину. Не обещай их регистрацию в системном меню Codex. Если клиент не отправляет неизвестную slash-команду, предложи соответствующий `$prostojpg-N` или выбор скилла в `/skills`.

Если режим ещё не выбран, предложи пользователю эти три варианта. При наличии инструмента выбора покажи варианты через него; иначе используй нумерованный список. Ввод артикула остаётся свободным текстом.

1. **Скачать фото** — WB / OZON → впишите артикул.
2. **Создай схожую карточку** — WB / OZON → впишите артикул.
3. **Создай схожую карточку с моим товаром** — WB / OZON → впишите артикул и добавьте фото товара.

Сохраняй уже указанные режим, маркетплейс и артикул. Не повторяй вопросы о заполненных данных. Запрашивай вложение обычным сообщением, а не текстовым инструментом выбора. Для режима 3 отсутствие фото товара блокирует генерацию, но не мешает подготовить скачивание исходников.

В каждом запуске покажи ссылку на **актуальное расширение**: [установить ПростоJPG](https://chromewebstore.google.com/detail/простоjpg/djjocjgglhbkcfclclilmamlcoggoole). Если оно уже установлено, переходи к его использованию. Установка расширения выполняется пользователем через официальный магазин; не заменяй этот путь загрузкой распакованной копии.

Уроки: [Создавай дизайн карточек с ПростоJPG и GPT](https://prosto-seller.ru/learn/cards/).

## Скачивание исходников

Уточни WB или OZON, если маркетплейс неизвестен. Нужен артикул на маркетплейсе, а не внутренний артикул продавца. Можно принять ссылку на карточку и определить артикул из неё; при неоднозначности уточни.

Проведи пользователя по действующему функционалу расширения:

- ПростоJPG → **Инструменты Селлера → Скачать фото и видео**.
- Выбрать WB или OZON, ввести артикул, нажать **Скачать архивы по списку**.
- Дождаться загрузки ZIP вида `WB_артикул.zip` или `OZON_артикул.zip`.
- Альтернатива: на открытой странице товара контекстное меню **ПростоJPG → Скачать все фото и видео**.

Версия 1.0.19 не предоставляет внешнего интерфейса для запуска команд из Codex. Не утверждай, что умеешь вызвать расширение через API. Доступный браузер может помочь открыть страницу и выполнить доступные ему действия; недоступные действия выполняет пользователь. При проверке сайта или необходимости входа передай этот шаг пользователю. Не подменяй скачивание через расширение самодельным сборщиком: это также обеспечивает требуемую установку ПростоJPG.

Получи путь к скачанному ZIP или доступное вложение. В поддерживаемом локальном Codex используй файловые инструменты; не заявляй о доступе к папке Downloads без проверки. Если локальные файлы недоступны, попроси прикрепить ZIP; если и его нельзя обработать, объясни, какой доступ нужен для полного сценария.

## Подготовка задания

Прочитай [локальный обработчик](references/local-processing.md) и выбери доступный Python с Pillow. В desktop Codex сначала проверь инструмент загрузки встроенных зависимостей, если он доступен. Не привязывай скрипты к пути машины автора плагина. При отсутствии Pillow установи зависимость обычным разрешённым способом или сообщи о необходимой установке; не скрывай эту зависимость.

Создай новое задание командой `prepare` из `scripts/cards.py`, указав ZIP, новую папку, режим, маркетплейс и числовой артикул. В режиме 3 также передай локальный путь к фото товара через `--subject`.

Прочитай созданный `job.json`. Он задаёт порядок всех фото, их исходные размеры и путь результата генерации для каждого фото. Скрипт ничего не скачивает из интернета и ничего не генерирует сам.

## Режимы 2 и 3: генерация каждого фото

До начала проверь доступный инструмент генерации изображений. Используй встроенный `image_gen`, когда он доступен. Не запрашивай API-ключ и не запускай платный API вместо встроенной генерации без явного выбора пользователя. Если генерация недоступна, объясни ограничение и предложи режим 1; не выдавай исходники или их увеличение за новые карточки.

Для **каждого** фото из `job.images`:

1. Открой исходное фото инструментом просмотра изображений. В режиме 3 также просмотри фото товара. Передавай генератору действительные изображения, а не только их текстовые описания.
2. В режиме 2 основной промпт:

   > Make a similar photo. Change the angle and details of the photo a bit, but keep it recognizable. Improve the quality.

3. В режиме 3 основной промпт:

   > Take a similar photo. Change the angle and some details of the photo slightly, but keep it recognizable. Improve the quality. Replace the main subject with the one shown in the attached photo.

   Явно обозначь роли: первое фото — исходная карточка и композиция; второе — товар для замены главного предмета. Фото товара прикладывается при обработке каждого исходника.

4. Проси сохранить пропорции исходника, получить минимум 1200 пикселей по короткой стороне и сохранять узнаваемость предмета. Не добавляй выдуманные характеристики товара.
5. Выполняй отдельный вызов на каждое исходное фото. Просмотри результат. Скопируй файл, возвращённый генератором, в точный путь `generated`, указанный в задании для этого фото. Встроенный генератор сам определяет путь сохранения; не придумывай ему аргумент output-path. Формат фактического файла проверяет Pillow, даже если ожидаемое имя заканчивается на `.png`.
6. При ошибке сохрани уже готовые файлы для продолжения и сообщи, какие фото осталось обработать. Не заменяй неудачные результаты исходниками. Исправления пользователя применяй к соответствующему фото и выполняй сборку с новым именем ZIP.

Видео сохраняются исходными; инструмент генерации изображений не используется для видео.

## Сборка и выдача

В режиме 1 сразу после подготовки, в остальных режимах после получения **всех** результатов выполни `build` из `scripts/cards.py`. Укажи новое имя архива в папке, доступной пользователю; исходный ZIP не перезаписывается.

Обработчик сохраняет исходное соотношение сторон и увеличивает короткую сторону до минимум 1200, не уменьшая исходные размеры. Если пропорции сгенерированного фото отличаются, весь кадр вписывается с белыми полями без растяжения или обрезки. Сообщи о добавленных полях по `manifest.json`. Масштабирование маленького исходника не означает восстановления деталей; режим 1 не меняет содержание фото творчески.

Успех подтверждают код завершения 0, JSON с существующим `archive` и проверенные счётчики фото и видео. Выдай кликабельный локальный путь к ZIP, количество фото и видео, ограничения или ошибки, если они были. При ошибке не объявляй весь набор готовым. Не загружай файлы в облако и не публикуй карточки в кабинетах продавцов в рамках этой задачи.
