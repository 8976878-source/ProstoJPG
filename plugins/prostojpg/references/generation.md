# Обработка и сохранение загруженных фото

Ресурсы находятся в `scripts/` корня плагина, рядом с `skills/`. Найди их относительно прочитанного SKILL.md (`../../scripts/`). В Claude Code доступен `${CLAUDE_PLUGIN_ROOT}`. В установленном Codex используй фактический путь пакета: не предполагай конкретный путь к кэшу.

## Подготовка

С версии 2.0 используются режимы 1/2/3 и job.json версии 2. Старые задания не переиспользуй под новой нумерацией; подготовь новое задание из сохранённых исходников.

Создай новую папку задания на компьютере пользователя; не перезаписывай существующие фото. Сохрани доступные вложения локально. Скрипты принимают уже локальные файлы, а не недоступные ссылки из веб-чата. Если среда не предоставляет файл вложения, попроси загрузить его доступным способом.

Нужен Python 3.11+ с Pillow. В Codex сначала используй доступный встроенный Python/Pillow. В Claude Code проверь установленный Python. Если Python отсутствует, помоги установить его, если это разрешено пользовательским запросом и средой. Pillow подключай только при первом запуске обработки (`python -m pip install "Pillow>=10.4,<13"`). Установка самого плагина этих зависимостей не требует.

Подготовка отдельных фото (артикул не требуется):

```text
python "<plugin>/scripts/uploads.py" --mode 1 --job-dir "<new-job>" --photos "<source-1>" "<source-2>"
python "<plugin>/scripts/uploads.py" --mode 2 --job-dir "<new-job>" --photos "<source-1>" "<source-2>" --subject "<my-product>"
python "<plugin>/scripts/uploads.py" --mode 3 --job-dir "<new-job>" --photos "<source-1>" "<source-2>" --subject "<my-product>"
```

Для исходного ZIP заменяй `--photos ...` на `--archive "<archive.zip>"`. Фото товара всегда передавай отдельным `--subject`. Подготовка сохраняет порядок и размеры исходников, проверяет ZIP и создаёт `job.json`; ZIP не распаковывай произвольным обходящим проверку способом. Видео не участвуют в генерации.

## Генерация в Codex

Используй встроенный инструмент генерации/редактирования растровых изображений Codex, если он доступен (например, `image_gen.imagegen`). Не выбирай текстовую модель вместо инструмента изображений и не привязывай навык к предположению о конкретном имени модели.

Для каждого `job.images` просмотри исходное изображение, затем редактируй по встроенному промпту выбранного навыка. В режиме 1 передай одно исходное фото; в режимах 2 и 3 — исходник и фото товара в указанном порядке. Режим 2 меняет внешность модели, режим 3 сохраняет человека и его лицо; не смешивай их промпты. В режиме 3 сравни лицо и причёску с исходником перед выдачей; если модель изменилась, исправь результат или сообщи о неудаче. Для локальных исходников используй `referenced_image_paths`; для вложений без локального пути — поддерживаемый инструментом способ ссылок на изображения. Не сочетай два взаимоисключающих способа.

Попроси сохранить исходное соотношение сторон и достаточную детализацию для короткой стороны 1200 px. Дождись фактического результата каждого изображения. Сохрани только реальное сгенерированное изображение по пути `generated/0001.png` и далее из `job.json`. Если формат результата отличается, сохрани реальный формат или конвертируй готовый результат без изменения композиции. Не редактируй фото рисованием на Python.

Если встроенный инструмент в текущем клиенте не представлен, допустим тот же установленный Codex App Server, что используется для Claude Code ниже. Если нет обоих путей, объясни отсутствие генератора; не предлагай незапрошенный платный API как автоматическую замену.

## Генерация в Claude Code

Используй установленный Codex и аккаунт ChatGPT; сам Claude Code не предоставляет встроенный растровый генератор этого плагина. Дополнительный плагин генерации и API-ключ не нужны. Codex должен поддерживать App Server и инструмент imageGeneration, а аккаунт — иметь доступ к генерации.

```text
python "<plugin>/scripts/render_codex.py" --check
python "<plugin>/scripts/render_codex.py" --job-dir "<job>" --output-dir "<new-output-folder>"
```

Скрипт ищет Codex в PATH и в установленном приложении Windows. При необходимости передай `--codex-path "<codex executable>"`. Он проверяет доступ и вход, вызывает генерацию для каждого исходника и сохраняет отдельные JPEG после проверки размеров. Если нужен вход, предложи `codex login`; вход выполняется через официальное окно авторизации. Не читай и не копируй токены, не переключайся на API-аккаунт. При необходимости подтверждения закончи его в Codex, не обходи проверку.

Скрипт выводит прогресс; генерация может занять несколько минут на фото. Ожидай завершения процесса, сообщая о прогрессе, а не запускай его повторно. Наличие доступа к генерации зависит от версии Codex, аккаунта и лимитов; не гарантируй успешный рендер без фактического результата. Скрипт не фиксирует имя модели и принимает только завершённый `imageGeneration` с реальным файлом. Он уже экспортирует каждый готовый файл отдельно, без ZIP.

## Отдельные фото после встроенной генерации Codex

```text
python "<plugin>/scripts/cards.py" export --job-dir "<job>" --output-dir "<new-output-folder>"
```

Экспорт проверяет каждое сгенерированное фото; неполный набор не выдаётся как завершённый результат. Пропорции совпадают с оригиналом, короткая сторона каждого итогового фото всегда не менее 1200 px. Если генератор вернул другое соотношение сторон, добавляются белые поля без обрезки предмета — сообщи об этом по `manifest.json`. Увеличение разрешения само по себе не гарантирует новых деталей.

Всегда проверь размеры реально сохранённых итоговых фото: короткая сторона каждого не менее 1200 px. Если генератор вернул меньший файл, используй экспорт для масштабирования и сохранения пропорций. Покажи каждое итоговое изображение и дай отдельную ссылку на его локальный файл; финальный текст — «Готово.» или «Карточки готовы.» Не создавай ZIP после генерации ни для одного, ни для нескольких фото. Локальный manifest.json служит проверке и не прикладывается к ответу. Исходники остаются в папке задания. Изображения передаются сервису OpenAI для генерации, результат сохраняется на компьютере пользователя. Это готовые промпты и автоматизация; отдельная модель на тысячах карточек не обучалась.
